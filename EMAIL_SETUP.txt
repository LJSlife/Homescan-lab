HomeScan 2.7.1 — Activate the Gmail connection

STATUS
Normal Email screens now show a clear activation-pending state and simple
connection help. Technical setup is on the separate email-owner.html page.
The public Google Web client ID supplied by the app owner is now configured.
Real Gmail access still depends on the project permissions, enabled APIs,
authorised origin and test-user settings. These require live confirmation. ChatGPT's connected Gmail cannot be reused by
this website. Do not enter a Google password, client secret or API key into
HomeScan. A Web client ID is public and safe to include in email-config.js.

ONE-TIME OWNER SETUP
1. In https://console.cloud.google.com create/select a project.
2. Enable Gmail API and People API under APIs & Services > Library.
3. Configure Google Auth Platform branding, audience and data access. For
   personal testing, use External/Testing and add your Gmail address as a test
   user. Supply genuine app/support details requested by Google.
4. Create an OAuth client of type Web application. Add the website ORIGIN as
   an authorised JavaScript origin, e.g. https://ljslife.github.io (no path).
   For a local test add http://localhost:PORT separately. Use HTTPS when hosted.
   The Google Identity Services popup token flow needs no redirect URI.
5. Add the following data-access scopes:
   https://www.googleapis.com/auth/gmail.readonly
   https://www.googleapis.com/auth/gmail.send
   https://www.googleapis.com/auth/contacts.readonly
   https://www.googleapis.com/auth/contacts.other.readonly
6. Copy the client ID ending in .apps.googleusercontent.com into clientId in
   email-config.js and upload the updated file. Alternatively,
   use email-owner.html to generate email-config.js, then upload it to GitHub.
   Ordinary users are never asked for a client ID.
7. Open the app in Safari, Open email > Connect Gmail, select your account
   and grant read permission. The inbox loads automatically after connection. Sending and contacts request
   additional permissions only when used. Check Gmail Sent after your first
   explicitly reviewed send. No real email was sent during development.

Testing users may see an unverified-app warning. Do not release publicly on
the assumption that personal testing is production approval. Gmail read access
is a restricted scope. Public release needs the applicable Google verification,
privacy policy and any assessment Google requires for the architecture. Consult
Google's current policy and console guidance before broader distribution.

USING EMAIL
Open email from Home or More. Check inbox loads 20 messages at a time; Load more
continues. Default: unread inbox, excluding Google-classified Social, Spam and
Trash. Recent inbox shows the past 30 days. Include-social option still excludes
Spam and Trash. Promotions are retained, because receipts/delivery emails can
be useful. Gmail's classification can be imperfect. Checking never marks read.

Summaries select up to three key sentences on this device; they are extractive,
not an AI interpretation or a guarantee all important details were captured.
HTML is converted to plain text and rendered escaped; scripts, remote images
and tracking pixels are not displayed. Email content cannot invoke app actions.
Tap the envelope/Original link to open that thread in Gmail for the selected
account. Mobile Gmail/browser routing depends on your device; confirm it on
Safari once the Google connection is active.

Keep attachment saves original bytes in this browser. Optional automatic keeping
applies to messages loaded in the check, not every message in the mailbox.
Limits: 10 MB each, 50 MB saved per account. Skipped/failed saves are reported.
Larger files stay accessible from the original email. Find attachments by file
name, sender or subject; download originals without rendering executable files.
Attachment backups include files and message metadata with SHA-256 verification.
Restore requires the same selected Gmail account and imports atomically after
validating every file. Home and Memories backups do NOT include email attachments.
Keep all applicable backups outside the browser. Removing a saved attachment
never deletes it from Gmail. Clearing website data removes local files/drafts.

Write: choose a recipient from a searchable dropdown or type a new address.
Update Google contacts loads all paginated Contacts and Other contacts that
Google exposes. Google does not expose every address ever seen in Gmail as a
single universal list. The app also offers senders of checked emails. Multiple
independent Gmail mailboxes are connected separately through Switch account;
this version does not combine mailboxes or import Gmail send-as aliases.

To, Cc, Bcc, Subject and message support Speak. Review the transcript first,
particularly spelled email addresses. English (Ireland) is requested. Browser
speech recognition may use an online service; unavailable browsers can use the
phone keyboard microphone. Dictation replaces the selected field when accepted.

Drafts save per account locally. Review email shows exact recipients/subject/body.
Send this email is the explicit send action. If sending permission is newly
requested, review again afterwards. There is no automatic or voice-triggered
sending. There is no outbound attachment picker in this version. If a send's
response is lost, the app blocks another send of that draft: check Gmail Sent
before starting a new email. Confirmed send clears the local draft.

The current Google access token is stored in this app's local IndexedDB only so
closing and reopening the PWA does not immediately force another Gmail connection.
The stored token is a bearer credential and normally lasts about an hour; it is
removed on Disconnect, expiry, or a Google 401 response. It is not included in
HomeScan backups.

This remains a browser-only OAuth token flow. Google's current documentation says
a fresh access token after expiry must be requested from a user-driven action.
HomeScan therefore preloads Google Identity Services and, when possible, uses the
user's tap on Open email as that action to renew access using the already-saved
account hint. Google may still display its authorization dialog. If the Google
library is not ready at that instant, HomeScan shows Reconnect Gmail instead.

A true long-lived 'connect once and stay connected across days without another
Google authorization interaction' design requires Google's authorization-code
flow plus a secure backend that stores a refresh token. GitHub Pages alone cannot
securely provide that architecture.
